# v39：PowerShell 引号与压缩误判

本次真实错误包含两个独立阶段。

1. PowerShell 不使用反斜杠转义双引号。混入 bash 引号片段后，远端 `grep` 的 `|` 被 Windows 解析，`libandroid_runtime` 被当成本机命令调用。这个报错不能证明 Android 没有加载 ART。
2. 防护在每个正文增量中查找 `<tool_call>`，没有区分无工具的压缩摘要和实际工具任务。摘要引用了该标记便被中断；触发保护的文字还因先检查后记录而丢失。

修复内容：

- 无工具的压缩/摘要请求不进行伪工具调用拦截；带工具任务只在完整消息中判断裸调用结构。代码块、行内代码、引用及一般说明文字不触发拦截。
- 原生工具名、JSON 参数和必填字段的检查继续保留；时间、无输出与重复异常保护继续保留。
- 先保存模型真实输出，再进行防护检查，异常日志可追溯。
- 明确识别 PowerShell 的 `The term ... is not recognized ...`，即使进程返回 0 也记录为失败。
- 为模型增加 Windows 与嵌套 shell 的引号规则，要求使用 Python 参数列表，禁止根据失败的 Windows 命令猜测手机运行时状态。
- 提供 `tools/inspect_android_runtime.py`：只读诊断、动态读取当前 PID、在 Python 中筛选库文件，远端不拼 grep/awk 管道。设备或权限异常明确写入报告。

现有 v38 目录与故障日志保留；v39 沿用 16K 思考、32K 输出和独立会话文件夹设置。此改动不能保证模型永不生成错误命令。
