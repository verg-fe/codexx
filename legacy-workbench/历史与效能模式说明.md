# 历史与效能模式

“模型与性能”中选择“完整历史留存＋按需读取”，再选择工作上下文大小并点击应用。

- 默认工作上下文 32K，在约 24K 时由编程引擎整理当前历史。也可选择 16K、24K、48K、64K。
- 原始对话、工具记录和模型生成日志留在本地。历史搜索、分页读取和任务状态工具用于找回早期的原始信息。搜索范围限定在当前会话。
- 当前任务摘要与完整历史是分开的。摘要可能漏掉细节；遇到早期的精确数字、路径、约束，应调用历史工具查原文。
- 选择“完整上下文模式”可回到原来的长上下文滑条；两种模式分别保存设置。
- 这不是单次生成的思考上限。模型权重、现有量化、采样默认值和无限思考保持不变。一次特别长的推理仍会增长缓存并降低速度。

“极致效能 · 不超频”提高模型调度优先级，以六个物理核心准备输入，显卡解码使用两个 CPU 调度线程。不会修改系统超频、电压或显卡功耗设置。CPU 模型层卸载保持关闭。

“Jack MTP · 主模型验证”尝试利用现有 Jack 文件中的预测层，共享主模型权重。候选 token 必须通过主模型验证，程序不启用跳过验证的模拟接受模式。不需要下载另一个主模型。是否默认开启由短性能验证结果决定；其他模型使用常规输出。具体收益受输入内容、接受率和上下文长度影响。

显卡缓存优先处理实际较短的请求；很长的真实输入加输出预留空间超出显卡容量时仍需要内存缓存。内存容量无法替代显存带宽。界面所选的 256K 上限并不代表每次输入都有 256K。

原始会话：`D:\LocalCodex\codex-home\sessions`。生成日志：`D:\LocalCodex\logs\generation`。可重建的搜索索引和任务状态：`D:\LocalCodex\history`。

验证报告分别说明历史工具、实际编程引擎协议和短请求后端性能。短请求速度不能保证长推理过程始终保持同样速度，程序也不会用强制功耗代替实际速度验证。
