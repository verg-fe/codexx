# 我的 Codex：Jack / Huihui 本地双模型版

本机：AMD Ryzen 5 7500F、32GB 内存、AMD Radeon RX 9070 16GB 显存。模型位于 `G:\LocalCodex\models`；推理引擎和会话数据位于 `D:\LocalCodex`。源代码位于 `C:\Users\18213\Desktop\codexx`。

## 当前推理方式

“模型与性能”页现有“推理后端”下拉框，可选 Vulkan 或 AMD HIP · ROCm 10.0，然后点击“应用模型、后端与上下文”。切换会重新加载模型；失败时尝试恢复原设置。当前默认保留 Vulkan。HIP 程序及 RX 9070（gfx1201）依赖独立存放在 `D:\LocalCodex\runtime-hip`，不会改动系统 PATH。

HIP 已实测 Jack 的 109,568 token 显卡 KV 窗口、全部模型层在显卡、CPU 卸载关闭，并通过短文本回答、函数调用和 WebP 图片识别；随后已成功切回 Vulkan。验证结果在 `D:\LocalCodex\verification-hip18.json`。对话上限和自动缓存策略保持原设置；未进行 256K 长输入性能测试，不能据此承诺 HIP 比 Vulkan 更快。原推理指引、思考强度与不限 token 设置不变，保留“思考日志”页。旧草案 `research\hip-draft-16` 含有已撤回的推理策略修改，不应直接覆盖当前源码。

模型层全部在显卡运行，CPU 卸载与自动回退关闭。Jack 对话总上限为 256,000 token，自动模式按实际输入长度选择服务窗口：短输入使用 109,568 token 显存 KV；较长输入才加载完整内存 KV。Huihui Q4_K 不满足当前全 GPU 模式的显存余量要求，仍保留模型文件与选项，切换时会提示。分词、界面和编程工具仍会使用 CPU。

## 使用

双击桌面的“我的Codex.cmd”，选择项目文件夹并描述任务。Ctrl+Enter 发送；“停止”中断任务。命令与文件修改自动确认，新会话和恢复的旧会话均生效。对话按会话保存，左侧可继续历史会话。项目文件页支持查看文件、编辑、保存和查看差异；手动保存前会备份原文件。图片按钮可添加截图或图片。

左侧每条会话都有“删除”按钮，删除时不再二次确认；可用“撤销上次删除”恢复，重启后也能撤销。删除会移出列表、将显示记录移至 `D:\LocalCodex\conversations\deleted`，并归档对应的编程内核会话。撤销恢复原顺序、记录和原生会话。任务运行期间先完成或停止，再删除。

发送图片时兼容层会把当前解码器不支持的 WebP 等格式转成 PNG，保留图片内容与透明度；同样处理历史消息和工具结果中的图片。两种模型共用此修复，原错误 WebP 已在 Jack 实际请求中验证。Huihui Q4_K 仍受全显卡显存预检限制，图片格式修复不会自动开启 CPU 权重卸载。

模型页显示加载状态、下载进度和日志入口。“释放显存”关闭本软件启动的模型进程。关闭窗口会关闭编程引擎，模型继续驻留；重新打开时会复用模型。首次加载可能需要一些时间。

本软件是个人编程工作台，采用现有 Codex 的开源 app-server 内核，界面由本项目实现。它不是 OpenAI 官方桌面客户端的完整复制版。

## 模型与上下文

根据你的明确要求使用 [JackAgentLead/Jack-3.8-27B-V2-VL-16GB-VRAM](https://huggingface.co/JackAgentLead/Jack-3.8-27B-V2-VL-16GB-VRAM)。主模型 12,120,033,600 字节；BF16 视觉组件 931,146,528 字节。下载固定到仓库提交 `b5547a4b12824a1db2bf1af41504c3c7d600f8ac`，分别校验 SHA256 后启用。

保留模型自带模板和 Jack 协议，关闭 MTP，使用发布者建议先测试的 Q4 KV 缓存。Codex 的项目工具说明仍由编程内核提供；这与发布者建议用于基线测试的“外部系统提示词留空”有所不同。未重写或删除内置 Jack 模板。

已增加 Huihui Q4_K 选项与上下文滑条。Jack 当前总上限 256,000 token，Huihui 当前默认 20,480 token。全部极限测试已按你的要求停止；Jack 自动压缩阈值为 223,232 token。窗口是输入、历史、图片与输出共享的总量。历史验证记录见 [上下文极限测试报告](上下文极限测试报告.md)。

自动模式会使用当前模型的原始模板与分词器计数，包括系统说明、工具定义、工具结果和历史思考；图片按每张最多 2,048 token 预留。未指定总输出长度时额外留出 32,768 token 生成空间，输入加预留不超过 109,568 时使用显存 KV。预留量只影响缓存位置，不是思考或生成长度上限。接近边界时保留内存窗口，避免反复加载；对话缩短后会重新使用显存。无法可靠计数的请求使用完整窗口。

已按要求取消固定思考预算和适配器默认的 8,192 token 总输出限制；后端 reasoning budget 与 n-predict 均设为 -1。仍保留思考强度选项、等待正文状态和生成 token 计数。思考及输出仍占用实际服务窗口，无法在同一次生成过程中无缝扩展 GPU KV；跨请求的缓存切换会重新加载并重建上下文。真正接近 256K 的长输入依然使用内存缓存，不能保证与短输入相同的速度。

等待状态中的“本轮”秒数包括输入处理、等待、生成和工具操作；“当前生成”是当前推理请求的生成数量，包含思考与隐藏内容，不等同于可见正文长度。长时间没有正文时仍可能持续生成，不能仅凭计时或数量确认重复循环。

从此版本开始，Responses 流式请求会将模型实际返回的思考、正文和工具参数增量写入 `D:\LocalCodex\logs\generation\*.jsonl`，每个请求单独记录，停止或连接中断时保留已收到的部分。记录包含时间、运行窗口、结束原因和可用的生成统计，不保存请求输入或访问令牌字段；生成内容本身可能引用项目内容。写入过程只保留每个输出片段的字符计数与摘要校验值，不在内存积累完整思考。最终事件只补齐未流出的尾部，避免将全文反复写入。日志写入失败不停止模型。该功能不限制推理时间或长度，也无法追溯恢复旧请求未保存的内容。

“思考日志”页实时显示实际生成内容，区分思考、正文和正在生成的工具参数；可跟随最新请求，或选择最近的历史记录。界面仅保留最近 40,000 字符，通过增量读取更新；“导出完整日志”会生成可读的 TXT，并打开文件。导出位置为 `D:\LocalCodex\logs\generation-readable`。这里显示当前阶段与最新记录的时间，不估算固定完成百分比。此次只增加日志展示，保留原推理指引、思考强度和不限 token 设置。

优化包括：单推理槽位、Flash Attention、Q4 K/V 缓存、1 个状态检查点、稳定的工具前缀、保留思考历史、按需搜索与读取函数片段、工具输出上限 2,000 token、模型元数据明确标记视觉能力。当前槽位的 KV 前缀复用由 llama.cpp 管理；自动压缩由 Codex 管理。

针对压缩后系统内存上涨，关闭 llama.cpp 默认最高 8GB 的旧提示 RAM 缓存，关闭闲置槽位的额外历史快照，限制为 1 个状态检查点。桌面端在压缩、结束和出错时清理流式缓冲，对话记录增量写入磁盘；窗口只显示最近 160,000 字符，恢复旧会话时只读取尾部。网关请求结束后关闭连接，避免闲置连接线程继续持有旧请求。模型本体、当前 KV、图形驱动和状态检查点仍会常驻内存，内存占用不会降到零。有限次数测试只能检验该场景是否继续增长，不能证明所有场景都没有泄漏。

## 集成到已有 Codex

已有默认云端模型配置保留。添加独立的 `jack-local.config.toml` 配置后，可用 `codex -p jack-local` 启动本地模型会话。桌面个人版通过同一模型服务运行 app-server。模型监听 `127.0.0.1:8080`，Codex 使用 `127.0.0.1:8081/v1` 的本地兼容网关，均使用本机生成的访问令牌。网关支持原生 apply_patch 工具，并将系统消息整理到模板允许的位置。自动确认使用 never 策略和完整本机访问，模型调用命令与修改文件时无需逐次点 yes。

配置文件：`D:\LocalCodex\settings.json`、`D:\LocalCodex\codex-home\config.toml`。会话位于 `D:\LocalCodex\conversations` 与独立的 Codex 数据目录。无需 OpenAI API key；本地模型推理请求发送到本机。

## 有比原版 Qwen3.8-27B 更强的新模型吗？

有，但要区分任务质量、推理速度和本机可运行性。下面是截至 2026-10-02 检索到的发布者测试，不是这台电脑的实测，也不能跨测试框架直接换算。

| 模型 | 可核对的表现 | 本机适配判断 |
|---|---|---|
| [Qwen3.8-Flash-Next](https://huggingface.co/Qwen/Qwen3.8-Flash-Next) | 官方同组报告：SWE-bench Pro 62.5 对 27B 的 61.7；DeepSWE 58.7 对 42.2；多语言 SWE 81.0 对 73.8 | 总体 125B 参数，另有 51B n-gram 嵌入；每 token 激活 6B 不能当成只有 6B 权重。16GB 显存、32GB 内存不适合直接运行 |
| [GLM-5.3](https://huggingface.co/zai-org/GLM-5.3) | 发布者报告 DeepSWE 66.9、Terminal Bench 2.1 88.2；测试条件与 Qwen 的报告不同 | 大型模型，远超本机内存预算，适合服务端或远程 API |
| [MiniMax-M3](https://huggingface.co/MiniMaxAI/MiniMax-M3) | 发布者报告 SWE-bench Pro 59；这个指标不高于 Qwen3.8-27B 的 61.7，不能笼统称为全面超越 | 大型模型，不适合当前本机直接部署 |
| Jack V2 27B | 发布者介绍重点是状态整理、证据与工具流程；未发现足以证实全面超越原版的同条件公开基准 | 根据你指定的型号部署；主权重更小，保留视觉能力，适合在本机验证 |

本次选择 Jack V2 是遵循你的指定和本机内存约束，不是宣称它是所有任务的最强模型。
