# 根据问题选择工具

| 当前需要的证据 | 优先工具 | 判断依据 |
|---|---|---|
| 项目实现、构建错误、文件变化 | 原生文件工具、rg、构建器 | 先定位报错对应文件和行，不用截图代替编译输出 |
| 陌生 API 或版本差异 | search_web、read_webpage、实际安装源码 | 查询保留库名、版本、API 名和精确异常；阅读官方正文，不把搜索摘要当接口保证 |
| Windows 窗口、弹窗、焦点、操作效果 | windows_desktop Snapshot/Screenshot | 从当前截图或控件树定位；界面变化后刷新；只需要局部证据时缩小截图范围 |
| 手机界面、应用启动和崩溃 | 指定设备 ADB、无障碍树、截图、定向 logcat | 手机不使用 Windows MCP；核对包名、PID、日志时间和当前安装版本 |
| Android 运行时行为 | 已验证的 Python 3.12 Frida 客户端 | 先验证 USB 通道、目标进程和实际版本，区分客户端连接问题与脚本/API 错误 |
| 原生二进制函数和交叉引用 | ida_local MCP | 先确认当前 IDB，再查函数、字符串、反编译；没有本机二进制问题时无需启动 IDA |
| 构建隔离或工具版本冲突 | 现有虚拟机环境和其项目技能 | 先复用已安装组件；不要因新目录为空就认定环境缺失 |
| 旧会话进度、已生成代码 | 历史检查点、draft_list/draft_read、当前项目文件 | 压缩后先恢复进度和最新源码，避免用旧错误覆盖新证据 |

## 具体故障

- Windows PowerShell 5.1 的文本重定向会破坏 ADB 的 PNG 二进制输出。截图让子进程直接写 bytes，随后检查 PNG 签名和图片解码；文字命令优先使用工作台已配置的 UTF-8 PowerShell。
- `abstract ... has no body to hook` 表明方法没有可执行函数体。核实声明和实际实现、模块来源及目标进程，不把第三方模块日志自动算作当前项目失败，也不要重复对同一抽象方法操作。
- `ModuleNotFoundError` 先核对实际解释器和环境；文件占用错误先检查资源是否显式关闭；连接失败核对 PID、端口和健康结果。
- 正常思考或长构建有实际进展时继续等待。相同错误再次出现时比较具体错误和输入，换一个能区分原因的验证方法，不原样循环。

## 保存已经验证的知识

成功后用 skill_search 查已有技能，skill_read 获取当前 revision，合并后用 skill_save 和 expected_revision 保存。记录适用条件、版本、资源路径、复现症状、成功方法、验证证据和未验证部分。保存可复用结论与必要代码入口，不保存完整聊天、思维链、真实 token 或许可证密钥。

方法尚未验证时标为待验证；接口升级或资源迁移后重新验证并更新，不把旧经验当永远有效的规则。
